# Development

## Android CI cache

The Android workflow uses `gradle/actions/setup-gradle` to cache Gradle User Home,
including Wrapper distributions and downloaded dependencies. Only `main` writes
cache entries; pull requests, tags, and other branches restore them read-only.
The Gradle version still comes from the Wrapper generated by `npx expo prebuild`.
The generated Android project and signing files are not included in this cache.

To validate changes, run the workflow on `main` to populate the cache, then open a
pull request and inspect the setup-gradle restore logs and job summary. Both runs
must complete prebuild, `assembleRelease`, and APK artifact upload from a clean
checkout. Compare build duration and cache transfer sizes; a cache hit alone does
not establish a speedup. After changing Expo dependencies or the generated
Wrapper version, verify that the build resolves the required versions correctly.
Tag builds retain the existing separate GitHub Release upload job.
